Tutorial · about 10 minutes

Your first raycaster

In this tutorial you build Vault Runner — a complete retro first-person game with a vault gem, collectible coins, a patrolling sentinel, a locked exit and a scripted opening sequence. Everything happens in one HTML file with zero installs. If you get stuck at any point, the finished file lives at examples/vault-runner.votyer in the repo, and you can paste any step into the playground to see it run instantly.

1

The HTML shell

Create a folder, add a file called index.html, and download votyer.js from the repository next to it. Then wire the two together: the runtime is one script tag, and your game is a second script tag with a special type="text/votyer". The data-canvas attribute points at the canvas that should receive the game.

<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <title>Vault Runner</title>
  <style>
    body { margin: 0; background: #0b0b1e; display: grid;
           place-items: center; min-height: 100vh; }
    canvas { max-width: 100%; box-shadow: 0 20px 60px #000; }
  </style>
</head>
<body>

<canvas id="game"></canvas>

<script src="votyer.js"></script>
<script type="text/votyer" data-canvas="#game">
// ... your game goes here ...
</script>

</body>
</html>

Open the file in a browser right now and you should see a dark canvas with a votyer error panel — the script is empty, which is the compiler correctly telling you there is no game yet. Errors always render on the canvas with a line number, so debugging never requires the console.

2

The game block

Every votyer program starts with the game declaration. It names your game and tunes the feel: resolution, colors, fog density, movement speed. Replace the empty script with this:

game "Vault Runner" {
    size 800 500
    sky #14142a
    floor #3a2c22
    fog 0.5
    speed 3.0
}

Reload the page. The title screen boots immediately — animated stars, your game name in gradient letters, and CLICK OR PRESS ENTER TO START. Nothing happens when you start yet because there is no world, which is the perfect excuse for the next step. Notice that the fog value of 0.5 already gives the menu's background corridor a moody, dungeon-like feel — fog is one of the strongest mood dials in the engine.

3

Draw the map

The map block is ASCII art: # is wall, . is floor, and P marks where the player starts. We also declare one palette character — 1 — which becomes a rust-brick wall variant for a bit of visual variety.

palette {
    "1" #6d4a2f
}

map {
    "###########"
    "#P....1...#"
    "#.###.###.#"
    "#.#C...#c.#"
    "#.#.###..S#"
    "#...#.G.c.#"
    "###########"
}

Reload and press Enter — you are now standing inside the level in first person. Walk with WASD, turn with the arrows, and click the canvas once to enable mouse look. The letters C, c, S and G are currently rendered as plain floor because nothing claims them yet; they are reserved seats for the items, enemy and exit you will add below. Try bumping into walls — collision and sliding already work.

Level design tip. Keep corridors 2 tiles wide in play areas and 1 tile wide for tight mazes. If a row is shorter than the others, the engine pads it with floor automatically — but always seal the outer border, or rays will render the void.
4

Items and handlers

Two item blueprints claim the map letters: a gem on C and coins on c. The gem has an on take handler, which replaces the default pickup behavior — inside it, you have full control of what happens. The coins use the default behavior instead, which simply awards their value with a sound.

item "gem" {
    char "C"
    shape crystal
    color #5eead4
    value 50
    glow on
    on take {
        score += 50
        sound pickup
        say "The vault gem! Now the coins."
    }
}

item "coin" {
    char "c"
    shape orb
    color #fbbf24
    value 10
    on take {
        score += 10
        sound blip
    }
}

Walk into the gem: +50 points, a sparkle sound, and a toast at the bottom of the screen. Every sprite is drawn procedurally from the shape list — crystal, orb, star, chest — so there are no image files anywhere in your project. The glow on property adds a soft halo that makes pickups readable even in heavy fog.

5

Enemies

The S in the map is a sentinel. Enemies patrol until they have line of sight to you, then chase. Give it hit points so you can fight back, and a touch damage value with a matching rule later:

enemy "sentinel" {
    char "S"
    shape ghost
    color #e2445c
    speed 1.1
    sight 5
    hp 30
    damage 20
}

Approach it and it locks on — the chase state kicks in the moment it sees you, and walls genuinely block its vision. Fire with Space or a click: three hits (30 HP / 10 damage per blast) destroy it, complete with a white flash on every impact and a death animation. Health is the red bar top-left; touching the sentinel drains 20 points of it, and at zero you get the game-over screen. Try dying on purpose — the restart loop with Enter already works.

6

The exit and world rules

The G is the vault door — a portal that starts locked. The rules block wires the world's cause and effect: when the last item is taken, unlock it; touching the sentinel shakes the screen; kills pay 25 points; reaching the open door wins.

exit {
    char "G"
    color #8b5cf6
    locked on
}

rules {
    on all items taken {
        sound unlock
        say "The vault door grinds open!"
    }
    on touch enemy {
        shake 0.3
        say "Ouch — watch the sentinels!"
    }
    on enemy dead {
        score += 25
    }
    on reach exit {
        win
    }
}

This is the entire quest structure of the game, expressed in fourteen lines. Collect everything — the gem plus two coins — and the portal rumbles open by itself. Because the rule set is data, you can rebalance the whole game loop by editing text. Try adding a second on enemy dead line with if enemies left == 0 { say "Arena clear!" } to reward total domination.

7

Events, hints and endings

Finally the lifecycle events. on start runs on every launch and restart — perfect for a mission briefing delivered with wait timers. on win and on lose add a closing line before the end screens.

on start {
    say "Grab the gem and every coin."
    wait 3 {
        say "Then find the vault door."
    }
}

on win {
    say "Vault cleared like a pro."
}

on lose {
    say "The vault keeps its secrets."
}

That is the complete game. Reload, press Enter, and play it start to finish: grab the gem, sweep both coins, hear the vault unlock, dash past (or through) the sentinel, and escape through the portal. You have now touched every core concept in the language — blocks, items with handlers, enemy AI tuning, world rules and lifecycle events.

8

The full listing

Here is everything in one block to compare against — it is also examples/vault-runner.votyer in the repository, ready to paste into the playground:

game "Vault Runner" {
    size 800 500
    sky #14142a
    floor #3a2c22
    fog 0.5
    speed 3.0
}

palette {
    "1" #6d4a2f
}

map {
    "###########"
    "#P....1...#"
    "#.###.###.#"
    "#.#C...#c.#"
    "#.#.###..S#"
    "#...#.G.c.#"
    "###########"
}

item "gem" {
    char "C"      shape crystal
    color #5eead4 value 50
    glow on
    on take {
        score += 50
        sound pickup
        say "The vault gem! Now the coins."
    }
}

item "coin" {
    char "c"      shape orb
    color #fbbf24 value 10
    on take {
        score += 10
        sound blip
    }
}

enemy "sentinel" {
    char "S"      shape ghost
    color #e2445c
    speed 1.1     sight 5
    hp 30         damage 20
}

exit {
    char "G"
    color #8b5cf6
    locked on
}

rules {
    on all items taken {
        sound unlock
        say "The vault door grinds open!"
    }
    on touch enemy {
        shake 0.3
        say "Ouch — watch the sentinels!"
    }
    on enemy dead  { score += 25 }
    on reach exit  { win }
}

on start {
    say "Grab the gem and every coin."
    wait 3 { say "Then find the vault door." }
}

on win  { say "Vault cleared like a pro." }
on lose { say "The vault keeps its secrets." }
Note. Multiple properties on one line are fine — the parser only cares about tokens, not line breaks. Format your file however your team reads best.
+

Bonus: water & light (v1.1)

The v1.1 engine added the two features that make maps feel alive: animated water and dynamic lights. Both are one declaration away from the game you just built. Add a water block next to your palette, then flood a corridor with ~ tiles:

water {
    color #1a6f92
    wave 0.55
    reflect 0.7
}

map {
    "###########"
    "#P...~~...#"   // ~ tiles become animated water
    "#.##.~~.#.#"
    "#...C~~..G#"
    "###########"
}

Water tiles are walkable but slow you to 55% speed, splash when you enter, and tint the screen while you swim. They also come with two new rules — on enter water and on exit water — so you can script currents, warnings or a hidden trigger only swimmers can reach.

Lighting works the same way: give any item glow on and it becomes a real light source in the renderer. The classic recipe is torches — decor items that never get picked up:

item "torch" {
    char "t"
    shape torch
    color #ff9f43
    pickup off   // decor: stays in the world
    glow on      // flickering warm light
}

Finally, try ceiling off inside your game block: the dungeon opens to a gradient night sky with a twinkling starfield, and the water gets a sky to reflect. Combine all three — open sky, a water channel, a torch-lit hall — and your tutorial dungeon starts looking suspiciously like a real game. Paste any of these into the playground to see them in ten seconds.

Where to go next

You have a working game — now make it yours. Some ideas ordered by difficulty: add a second sentinel with shape robot and speed 2.0 for a real threat; give the gem a spawn "sentinel" x y ambush inside on take; build a bigger map with a palette story — rust outer ring, teal inner vault; or write an on tick pressure system that says something ominous every 30 seconds using time and random.

When you are ready for the full reference — every command, every shape, the JavaScript API — head to the docs. And if you build something fun, ship it: a votyer game is one HTML file, so GitHub Pages hosts it for free. Star or fork the repository if you want to follow the engine's progress.
